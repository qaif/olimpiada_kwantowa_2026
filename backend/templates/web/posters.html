{% extends "base.html" %} {% load static i18n %} {% comment %} „Plakaty do pobrania” (prośba organizatora z 23.09.2026). Siatka kart ``.cards`` z systemu interfejsu (``docs/UI.md`` § 2.4) – jedyne, co dochodzi w ``static/css/posters.css``, to ramka podglądu o stałych proporcjach, żeby karty z plakatem pionowym, poziomym i PDF-em bez miniatury stały w równym rzędzie. Podgląd ma pusty ``alt``: tytuł plakatu stoi tuż pod nim jako nagłówek karty, więc opis obrazka czytnik ekranu przeczytałby dwa razy. Ikona PDF-a jest ozdobą (``aria-hidden``) – format i rozmiar pliku stoją w tekście pod tytułem. Karta jest **jednym plikiem** albo **grupą plików** (``apps.promo.cards``): pliki z tą samą grupą („A3 · 297×420 mm”) stoją na jednej karcie – nagłówkiem jest grupa, podgląd to pierwszy podgląd w grupie, a każdy plik ma własny przycisk z wariantem i rozmiarem („Pobierz PDF · 2,6 MB”). Pierwszy przycisk jest główny, pozostałe drugoplanowe – żeby karta miała jedno oczywiste kliknięcie. Czytnik ekranu dostaje w nazwie przycisku także grupę (``visually-hidden``), bo lista linków „Pobierz JPG, Pobierz JPG, Pobierz JPG” z trzech kart nie mówi, który to plakat. Przycisk „Pobierz” prowadzi przez widok aplikacji (``web:poster-download``), a nie wprost do pliku: to widok liczy pobrania. Atrybut ``download`` jest wskazówką dla przeglądarki; nazwę pliku i tak ustala nagłówek ``Content-Disposition``. {% endcomment %} {% block title %}{% translate "Plakaty do pobrania" %}{% endblock %} {% block description %}{% translate "Plakaty i ulotki olimpiady do wydrukowania i powieszenia w szkole – pliki PDF, JPG i PNG do pobrania bez logowania." %}{% endblock %} {% block head %} {% endblock %} {% block content %}
