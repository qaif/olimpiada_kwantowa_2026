# T-03: Modele domeny zawodów

## Kontekst
Repo `backend/` (Django 5.1 + DRF). Istnieje `apps.accounts` (User, Participant, CommitteeMember, InvitationCode, grupy, uprawnienia). Konwencje jak w `docs/tasks/T-02.md`. Referencja modelu: `docs/PROJEKT.md` sekcja 2.2.

## Zakres
Nowa aplikacja `apps.competitions`:
- `Edition`: `year_label` (unique, np. "XV (2026/2027)"), `is_current` (tylko jedna edycja może być current – walidacja w `save()`/constraint).
- `Stage`: `edition` FK, `kind` ∈ {ELIM, DISTRICT, FINAL} (unique per edition), `opens_at`, `deadline_at`, `grace_seconds` (default 0), `review_deadline_at`, `appeal_window_opens_at`, `appeal_window_closes_at`, `results_published_at` (null). Walidacja kolejności: opens_at < deadline_at <= review_deadline_at <= appeal_window_opens_at < appeal_window_closes_at. Property `submission_deadline` = deadline_at + grace_seconds; metoda `is_open_for_submissions(now)`.
- `ScoringScale`: OneToOne Stage, `values` JSON (lista {value:int, label:str}), `max_value`; default `[0,2,5,6]` z etykietami OM. Metoda `allowed_values() -> set[int]`; walidacja: wartości unikalne, rosnące, 0 obecne, max_value == max(values).
- `QualificationRule`: OneToOne Stage, `mode` ∈ {MIN_POINTS, TOP_N, TOP_N_PER_DISTRICT, HYBRID}, `min_points`, `top_n`. Walidacja: MIN_POINTS wymaga min_points; TOP_N/TOP_N_PER_DISTRICT wymaga top_n; HYBRID wymaga obu.
- `Problem`: `stage` FK, `number` (unique per stage), `title`, `statement_pdf` (FileField, opcjonalny), `allowed_formats` JSON (default ["pdf"], dozwolone: pdf, ipynb, py), `max_file_mb` (default 20).
- `StageEntry`: `participant` FK, `stage` FK (unique together), `status` ∈ {REGISTERED, QUALIFIED, NOT_QUALIFIED, DISQUALIFIED}, `total_points` (null). Manager `for_user(user)`.
- Sygnał/serwis: przy tworzeniu Stage automatycznie tworzone są domyślne `ScoringScale` i `QualificationRule(mode=MIN_POINTS, min_points=0)` (w serwisie `create_stage(...)`, nie w sygnale post_save, żeby fabryki testowe były jawne).
- Serwis `register_for_stage(participant, stage) -> StageEntry`: tylko gdy stage.kind == ELIM i stage otwarty (opens_at <= now < submission_deadline); inaczej `DomainError(code="REGISTRATION_CLOSED", status 403)`; dla DISTRICT/FINAL wpisy tworzy kwalifikacja (T-07), ręczne → `DomainError(code="STAGE_NOT_OPEN_FOR_REGISTRATION")`.
- API (prefiks `/api/competitions/`), tylko odczyt dla zalogowanych, publiczny odczyt bieżącej edycji i etapów:
  - `GET editions/current/` → edycja + etapy (kind, opens_at, deadline_at, results_published_at) + zadania bieżącego etapu (bez statement_pdf jeśli etap jeszcze nie otwarty). AllowAny.
  - `POST stages/{id}/register/` → StageEntry dla zalogowanego uczestnika (IsParticipant).
  - `GET me/entries/` → wpisy zalogowanego uczestnika.
- Admin dla wszystkich modeli (inline ScoringScale/QualificationRule/Problem pod Stage).
- `manage.py seed_demo`: idempotentny (używa `get_or_create`), tworzy: edycję current z 3 etapami (ELIM otwarty teraz, deadline za 14 dni; DISTRICT i FINAL w przyszłości), 3 zadania w ELIM, 5 uczestników (hasło `Demo12345!`, e-maile `uczestnikN@example.com`) zarejestrowanych do ELIM, 3 recenzentów ACTIVE (`recenzentN@example.com`, okręgi: mazowieckie, małopolskie, mazowieckie), 1 koordynatora `koordynator@example.com` (superuser, grupa coordinator), 1 kod zaproszenia wypisany na stdout.

## Kryteria akceptacji (każde = test)
1. Dwie edycje `is_current=True` → ValidationError/IntegrityError.
2. `Stage` z `deadline_at < opens_at` → ValidationError przy `full_clean()`.
3. `ScoringScale` domyślna ma `allowed_values() == {0,2,5,6}`; wartości niemonotoniczne → ValidationError.
4. `QualificationRule(mode=TOP_N)` bez `top_n` → ValidationError.
5. `create_stage` tworzy domyślną skalę i regułę.
6. `register_for_stage` przed `opens_at` → 403 `REGISTRATION_CLOSED`; po deadline → 403; w oknie → StageEntry(REGISTERED); dla DISTRICT → `STAGE_NOT_OPEN_FOR_REGISTRATION`.
7. `POST stages/{id}/register/` drugi raz → 409 `ALREADY_REGISTERED`.
8. `GET editions/current/` bez logowania → 200 z etapami; nie zawiera danych uczestników.
9. `seed_demo` uruchomiony dwa razy nie duplikuje danych (liczby obiektów równe po 2. uruchomieniu).
