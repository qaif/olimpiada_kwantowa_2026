# T-08: Interfejs uczestnika i recenzenta (HTMX + pdf.js)

## Kontekst
Backend API z T-02..T-07 jest gotowy. UI ma być renderowane po stronie serwera (Django templates + HTMX + Alpine.js z CDN pinowanego wersją, bez bundlera). Jedyna „wyspa” JS: przeglądarka PDF z adnotacjami (pdf.js z CDN, warstwa adnotacji jako prostokąty na canvasie zapisywane do `Review.annotations`).

## Zakres
- Aplikacja `apps.web` (widoki HTML) i szablon bazowy `templates/base.html` (nawigacja zależna od roli, komunikaty, CSRF w HTMX przez `hx-headers`).
- Strony publiczne: `/` (strona główna z nawigacją do newsroomu i wyników), `/login/`, `/register/` (uczestnik), `/register/committee/` (z kodem), `/logout/`.
- Panel uczestnika `/me/`: bieżący etap, przycisk rejestracji do ELIM, lista zadań z treścią PDF, formularz uploadu per zadanie (HTMX, pasek statusu: PENDING/CLEAN/INFECTED, wersje), odliczanie do deadline'u (czas z serwera), wyniki własne po publikacji, formularz reklamacji w oknie.
- Panel recenzenta `/review/`: lista przydziałów z statusem; `/review/<id>/`: pdf.js po lewej (plik przez presigned URL / endpoint download), po prawej formularz: score (radio z etykietami skali), komentarz wewnętrzny, komentarz dla uczestnika, lista adnotacji (dodawane przez zaznaczenie prostokąta na stronie), zapis DRAFT (HTMX PATCH) i „Wyślij ocenę” (POST submit) z potwierdzeniem.
- Panel koordynatora `/coordinator/`: przyciski: zamknij etap, przydziel recenzentów, lista MODERATION z rozstrzyganiem, lista PENDING komitetu z zatwierdzaniem, publikacja wyników z wyborem anonimizacji, generowanie kodu zaproszenia (kod pokazany jednorazowo).
- Panel komisji odwoławczej `/appeals/`: lista reklamacji, decyzja.
- Wszystkie widoki używają serwisów/permission z poprzednich tasków (bez duplikowania logiki w widokach). Wszystkie formularze POST z CSRF.

## Kryteria akceptacji (testy `django.test.Client`, sprawdzanie statusów i kluczowych fragmentów HTML)
1. Niezalogowany na `/me/`, `/review/`, `/coordinator/` → 302 do `/login/`.
2. Uczestnik na `/review/` i `/coordinator/` → 403; recenzent na `/coordinator/` → 403.
3. `/me/` uczestnika z seed_demo zawiera nazwy zadań i formularz uploadu; po deadline formularz nieobecny, komunikat o zamknięciu.
4. Upload przez formularz (multipart) → nowy wiersz wersji w odpowiedzi HTMX.
5. `/review/<id>/` recenzenta zawiera radio ze wszystkimi wartościami skali i NIE zawiera nazwiska uczestnika.
6. POST submit oceny przez UI → Review SUBMITTED.
7. Koordynator: POST „przydziel” → Review utworzone; POST „publikuj” → ResultsPublication.
8. Strona wyników publicznych `/results/<stage_id>/` renderuje snapshot bez logowania.
