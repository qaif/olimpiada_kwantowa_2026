# T-06: Reklamacje (procedura odwoławcza)

## Kontekst
Repo `backend/`. Istnieją `apps.accounts`, `apps.competitions`, `apps.submissions`, `apps.grading` (Review, FinalGrade, AuditLog). Referencja: `docs/PROJEKT.md` 2.4 (sekcja „Reklamacje”).

## Zakres
Nowa aplikacja `apps.appeals`:
- `Appeal`: `submission` FK, `filed_by` Participant, `filed_at`, `argument` (min. 50 znaków), `status` OPEN/IN_REVIEW/REJECTED/ACCEPTED/PARTIALLY_ACCEPTED. `unique_together (submission, filed_by)`.
- `AppealDecision`: OneToOne Appeal, `committee` M2M CommitteeMember, `decided_by` User, `new_score` (null = bez zmiany), `justification`, `decided_at`.
- Serwis `file_appeal(user, submission, argument)`:
  - submission musi należeć do uczestnika (inaczej 404), status GRADED_PROVISIONAL, `stage.appeal_window_opens_at <= now < stage.appeal_window_closes_at` (inaczej 403 `APPEAL_WINDOW_CLOSED`); istniejąca reklamacja → 409 `APPEAL_ALREADY_FILED`.
  - tworzy Appeal(OPEN), Submission → APPEALED, AuditLog.
- Serwis `decide_appeal(appeal, actor_member, status, new_score, justification)`:
  - actor musi mieć `is_appeals_committee=True` i status ACTIVE; nie może być autorem Review rundy 1 ani 2 tej Submission → 403 `CONFLICT_OF_INTEREST`;
  - `new_score` w skali etapu (inaczej 400); ACCEPTED/PARTIALLY_ACCEPTED wymagają `new_score` różnego od obecnego; REJECTED wymaga `new_score is null`;
  - tworzy AppealDecision; jeśli new_score: aktualizuje FinalGrade(score=new_score, method=APPEAL, rationale=justification, decided_by=actor.user); Submission → FINAL (niezależnie od wyniku reklamacji); AuditLog z diffem {old_score, new_score}.
- Serwis `finalize_unappealed(stage)`: po `appeal_window_closes_at` wszystkie GRADED_PROVISIONAL → FINAL. Celery beat task `finalize_closed_appeal_windows` co 5 minut.
- API:
  - `POST submissions/{id}/appeal/` {argument} (IsParticipant) → 201.
  - `GET me/appeals/`.
  - `GET appeals/` (IsAppealsCommittee): lista OPEN/IN_REVIEW z `participant_public_code`, obiema ocenami rundy 1 (score + comment_internal), FinalGrade, argumentem, download URL pliku. Recenzenci z konfliktem interesów nie widzą tej reklamacji na liście.
  - `POST appeals/{id}/decide/` {status, new_score?, justification}.
- Rozszerzenie `Submission.objects.for_user`: członek komisji odwoławczej → Submission z Appeal bez konfliktu interesów.
- Uczestnik po decyzji widzi: status, `justification`, nowy wynik (`GET me/submissions/` rozszerzone o `final_grade` i `appeal`).

## Kryteria akceptacji (każde = test)
1. Reklamacja w oknie → 201, Submission APPEALED, Appeal OPEN.
2. Przed `appeal_window_opens_at` i po `closes_at` → 403 `APPEAL_WINDOW_CLOSED`.
3. Druga reklamacja → 409 `APPEAL_ALREADY_FILED`.
4. Reklamacja na cudzą Submission → 404.
5. `argument` < 50 znaków → 400.
6. Autor Review rundy 1 próbujący decydować → 403 `CONFLICT_OF_INTEREST`; nie widzi jej też w `GET appeals/`.
7. ACCEPTED z new_score=6 → FinalGrade.score == 6, method APPEAL, Submission FINAL, AuditLog zawiera {old_score, new_score}.
8. REJECTED → FinalGrade bez zmian, Submission FINAL.
9. `new_score` spoza skali → 400 `SCORE_NOT_IN_SCALE`.
10. `finalize_unappealed` po zamknięciu okna zmienia GRADED_PROVISIONAL → FINAL, nie rusza APPEALED.
