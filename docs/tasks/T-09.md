# T-09: Część informacyjna (Wagtail)

## Kontekst
Dodanie Wagtail (wersja zgodna z Django 5.1, np. 6.3 LTS) jako CMS in-process. Wagtail admin pod `/cms/`, strony pod `/`; istniejące ścieżki aplikacji (`/me/`, `/review/`, `/api/`, `/admin/`) mają pierwszeństwo w `config/urls.py` przed catch-all Wagtail.

## Zakres
- `apps.cms`: modele stron: `HomePage` (hero, skróty do bieżącego etapu i wyników), `NewsIndexPage` + `NewsPage` (data, lead, treść StreamField: akapit, obraz, załącznik, embed), `ProblemsPage` (renderuje zadania bieżącego otwartego etapu z `apps.competitions`, plus treści dodatkowe), `ArchiveIndexPage` + `ArchiveEditionPage` (edycja FK do `Edition`, treści zadań i rozwiązań jako dokumenty, link do opublikowanej tabeli wyników), `ResultsPage` (lista etapów z opublikowanymi wynikami, embed tabeli ze snapshotu).
- Migracja tworząca drzewo stron (Home → Aktualności, Zadania, Archiwum, Wyniki) i ustawiająca Site.
- Dokumenty i obrazy Wagtail w `public-media` (django-storages S3 dla `default` storage w produkcji; lokalny w testach). Bucket `submissions` pozostaje niedostępny dla Wagtail.
- Grupy: `coordinator` dostaje uprawnienia Wagtail Editors+Moderators (migracja danych). Recenzenci i uczestnicy nie mają dostępu do `/cms/`.
- Szablony spójne z `templates/base.html` z T-08.

## Kryteria akceptacji
1. `/` → 200, zawiera linki do Aktualności/Zadania/Archiwum/Wyniki.
2. Utworzony przez test `NewsPage` jest widoczny na `/aktualnosci/` i pod własnym slugiem.
3. `/zadania/` pokazuje zadania otwartego etapu; przed `opens_at` pokazuje komunikat, nie treści PDF.
4. `/archiwum/<slug>/` renderuje edycję i link do wyników, jeśli opublikowane.
5. Uczestnik na `/cms/` → 302/403; koordynator → 200.
6. Szablon `ResultsPage` nie renderuje niczego poza snapshotem (test: brak e-maila w HTML).
